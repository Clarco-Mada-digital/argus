Huit regards sur le même code

Chaque dimension est notée séparément, puis pondérée. Vous savez où porter l'effort.

Sécurité

Secrets versionnés, injections SQL et commandes, XSS, désérialisation, cryptographie faible. Chaque constat porte son CWE et sa catégorie OWASP.

Routes mortes

Liens internes qui ne mènent nulle part, pages qu'aucun lien n'atteint, routes déclarées deux fois, page 404 absente.

Code mort

Fichiers jamais importés, exports que personne ne consomme, code inatteignable, restes de débogage oubliés.

SEO

Balises, hiérarchie des titres, données structurées, robots.txt, sitemap — et les applications qui servent une page vide aux robots.

Accessibilité

Contrastes WCAG calculés, avec une couleur de remplacement proposée. Libellés, navigation clavier, responsive.

Dépendances

Vulnérabilités réelles via OSV.dev, scores CVSS calculés depuis le vecteur officiel, paquets abandonnés.

Il connaît votre framework

Vingt packs de règles dédiés, du serveur au natif. Chacun a été validé contre un projet réaliste construit pour l'occasion — et les faux positifs mesurés avant livraison.

Front et rendu

React

Jeton rangé dans localStorage — une faille XSS suffit à voler la session. Liste sans key, href construit depuis une valeur externe.

Next.js

ignoreBuildErrors, images.domains: ['*'], route d'API traitant un GET comme un POST.

Nuxt

Secret sous runtimeConfig.public — sérialisé vers le navigateur. ssr: false qui vide vos pages pour les robots.

Astro

set:html, client:only qui saute le rendu serveur, secret injecté par vite.define.

SvelteKit

Le retour de load() part dans le navigateur — malgré le nom .server. Et {@html}.

Angular

bypassSecurityTrustHtml — le seul moyen de désactiver l'assainissement d'Angular.

Serveur

Django

SECRET_KEY en dur, formulaire sans {% csrf_token %}, {% url %} vers une route inexistante, N+1 de l'ORM.

Flask

Clé de session en dur, aucune protection CSRF — Flask n'en fournit pas. send_file depuis la requête.

FastAPI

allow_origins=["*"] avec allow_credentials=True : combinaison interdite par la spécification.

Laravel

env() hors de config/ — renvoie null après config:cache, silencieusement.

Rails

config/master.key versionné, interpolation dans un where(), params.permit!.

Spring Boot

Actuator ouvert : /heapdump expose en clair tous les secrets chargés en mémoire.

Express

dotfiles: 'allow' qui sert .env et .git/config. Trace d'exception renvoyée au client.

Mobile et bureau

React Native · Expo

AsyncStorage porte un nom rassurant mais écrit en clair : un jeton s'y lit sans effort sur un appareil rooté. WebView avec accès au disque.

Flutter

Même piège, autre nom : SharedPreferences est un XML en clair. Et badCertificateCallback => true, qui désactive toute la validation TLS.

Tauri

"all": true dans l'allowlist réduit à néant le modèle de sécurité entier de Tauri. Shell exposé, csp: null, IPC ouvert à un domaine distant.

Electron

nodeIntegration, contextIsolation: false, webSecurity: false. Le renderer affiche du HTML ; s'il a aussi Node, toute XSS devient une exécution de code.

Kotlin · Swift natifs

Un checkServerTrusted au corps vide ne lève jamais d'exception : par contrat, cela signifie « certificat valide ». Tous le sont donc. Plus UserDefaults, SharedPreferences, trousseau trop accessible.

Manifestes Android · iOS

Règle transverse sur les manifestes natifs, quel que soit l'outil qui les a générés : trafic en clair, debuggable, allowBackup, ATS désactivé. Couvre aussi Capacitor, Ionic, Kotlin et Swift.

L'origine de la valeur, pas seulement le motif

db.query('… WHERE id = ' + identifiant) est une faille si identifiant vient de la requête, et n'est rien du tout si c'est une constante du module. Les deux remontaient en critique — et un faux positif critique est le plus coûteux de tous : c'est celui qui fait ignorer la catégorie entière.

Argus suit désormais les portées et l'origine des valeurs, en JavaScript/TypeScript et en Python. Une constante littérale ne remonte plus ; une valeur venue de l'extérieur est signalée avec certitude ; un paramètre de fonction est signalé, mais en confiance réduite — son appelant est inconnu. Le masquage par paramètre, la réaffectation et la déstructuration sont pris en compte.

Ce n'est pas un analyseur syntaxique complet, et c'est délibéré : aucun arbre, pas de précédence, pas de suivi inter-fonctions. Une seule question, bien traitée.

Les monorepos, application par application

Un dépôt qui contient plusieurs applications n'était en pratique pas analysé : la détection ne lisait que le manifeste racine, lequel ne déclare souvent qu'un orchestrateur. Un dépôt Next.js + Expo se résumait à « node ».

Chaque application est désormais jugée sur ce qu'elle déclare — et les conventions (pages d'un routeur, robots.txt) sont testées relativement à l'application, plus depuis la racine du dépôt. Le graphe d'imports, lui, reste global : un composant partagé que plus personne n'importe est bien mort.

Installable, et vraiment hors ligne

L'analyseur tourne entièrement dans l'onglet : aucun fichier ne part sur le réseau. Il n'y avait donc aucune raison qu'il ait besoin du réseau pour se charger. Installez-le, coupez le Wi-Fi, il analyse toujours vos dossiers — la promesse de confidentialité devient vérifiable au lieu d'être déclarative.

83 ressources précachées, dont les 62 modules du cœur d'Argus. La liste est générée au déploiement, jamais écrite à la main, et la version du cache est l'empreinte du contenu.

Une application mobile n'est pas un site web

React Native dépend de react. Sans distinction, Argus en concluait « SPA » et reprochait à une application mobile son robots.txt absent, son sitemap.xml absent et son défaut de rendu serveur. Quatre constats, tous absurdes.

Il détecte désormais la plateforme visée — web, mobile, bureau — et l'affiche dans le rapport. Le SEO ne s'applique qu'au web, les manifestes natifs qu'au mobile. Un projet Capacitor, qui est légitimement les deux, reçoit les deux.

Un piège commun à tous les outils de construction. NEXT_PUBLIC_, VITE_, PUBLIC_, REACT_APP_, GATSBY_, EXPO_PUBLIC_… Ces préfixes ne sont pas des espaces de noms : ce sont des publications. Une clé nommée …_SECRET_KEY devient lisible via « afficher le code source ». Une seule règle couvre les huit écosystèmes — et écarte les faux amis comme PUBLIC_KEY ou PUBLISHABLE.

Trois façons de s'en servir

Dans le navigateur

Choisissez un dossier de votre ordinateur. Rien n'est envoyé : la page n'a pas de serveur.

Ouvrir l'analyseur

En ligne de commande

Aucun clone, aucune installation. Node.js 18 ou plus récent.

npx github:Clarco-Mada-digital/argus scan .

Dans votre CI

Ne juger que ce que la pull request ajoute.

- uses: Clarco-Mada-digital/argus@main
  with:
    since: origin/main
    fail-on: medium
Rien ne quitte votre machine. L'analyse est entièrement locale. Deux commandes optionnelles utilisent le réseau — sync (base de vulnérabilités OSV) et crawl (audit d'un site en ligne) — et elles ne transmettent jamais votre code.

Langages

JavaScript, TypeScript, Python, Java, Kotlin, Dart, PHP, Go, Ruby, C#, Rust, HTML, CSS — et les gabarits Blade, ERB, Twig et Jinja, analysés comme des pages.

Ce qu'il ne fait pas

Argus fait de l'analyse statique et lexicale : pas d'arbre syntaxique complet, pas d'exécution de votre code. Les constats marqués « tentative » demandent une lecture humaine, et les liens construits à l'exécution ne sont pas résolus. C'est le prix d'un outil qui répond en une seconde, sans rien installer.
